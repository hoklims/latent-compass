# Synthetic benchmark corpus `synthetic-v1`

**This corpus is a pipeline demonstration. It is not evidence about anything.**

It contains no real agent behaviour, no real outcomes and no real costs. Every
number in it was chosen by hand to make the HOK-188 harness's behaviour — and
particularly its refusals — reachable and readable. A result measured on this
corpus supports **no** claim that any baseline is good, that one baseline beats
another, or that Latent Compass improves an agent's outcomes.

## Reproducing it

```bash
uv run python tests/corpus_generator.py
```

`tests/test_synthetic_corpus.py` regenerates the corpus into a temporary
directory and asserts that every committed file matches byte for byte. Editing
any file here by hand breaks that test, which is the intent: the generator is
the source, these files are its output.

## Contents

| File | Split | Cases |
| --- | --- | --- |
| `train.json` | `TRAIN` | 6 |
| `validation.json` | `VALIDATION` | 16 |
| `holdout.json` | `HOLDOUT` | 8 |
| `manifest.json` | — | seals, counts and groups derived from the three files above |
| `protocol.json` | — | the HOK-181 pre-registration governing the benchmark |
| `spec.json` | — | the HOK-188 benchmark plan bound to that protocol and this corpus |

The three splits are in **physically distinct files**, share no `case_id` and no
`episode_id`, and each seals to a distinct value computed from the cases
themselves.

## What the validation split is shaped to exercise

The 16 validation cases sit in three distribution strata — `nominal` (8),
`shift.long-horizon` (4) and `shift.high-uncertainty` (4) — and 5 of them are
marked ambiguous. Every corpus-derived eligibility state occurs at least once;
out-of-support is exercised as a whole-run refusal under a stricter test spec:

| State | Case | Why |
| --- | --- | --- |
| `ELIGIBLE` | most | outcome observed by the cutoff, complete, target action supported |
| `UNOBSERVABLE` | `case-val-06` | observability `NONE` — the outcome could never have been seen |
| `CENSORED_IMMATURE` | `case-val-07` | observed, but after this case's observation cutoff |
| `INCOMPLETE_OUTCOME` | `case-val-08` | observed, but carrying no violation count |
| `OUT_OF_SUPPORT` | `case-val-09` under the hostile `0.02` floor | its canonically-first direction has propensity `0.015625`; the run refuses rather than excluding that case from only `fixed-canonical` |

Candidate propensities are dyadic rationals (`0.5`, `0.25`, `0.375`,
`0.015625`, …), so each case's distribution sums to exactly `1.0` in binary
floating point rather than within a tolerance.

## Known limits of any result taken on this corpus

- **It is tiny.** 16 validation cases across 3 strata. No interval computed on
  it would be narrow enough to separate two baselines.
- **The logging policy is invented.** The propensities were written down, not
  measured, so the single assumption inverse propensity scoring rests on is true
  here by construction and unverified anywhere else.
- **Outcomes are stipulated.** Success, violations, cost, information gain and
  reversibility were chosen to vary, not observed.
- **The declared thresholds in `protocol.json` are arbitrary.** Their seal
  detects edits but does not prove they predate data access; this synthetic
  demonstration has no external chronology anchor. A baseline that fails one
  here has not been shown to be bad.
- **No external judge.** Every case declares `external_verdict` redacted, since
  there is no deterministic judge behind this data.

A corpus that could carry a claim would have to be real, larger, and drawn from
a logging policy whose propensities were recorded rather than authored. That
corpus is not in this repository.
